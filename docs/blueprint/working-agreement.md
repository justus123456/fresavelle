# Working agreement

Source: the user's working instructions supplied in chat, 2 November 2026, plus the subsequent Stage 0 instruction. This is a maintained summary; it does not replace the original instructions.

- Work in small reviewable stages. Before each stage explain in simple language what and why, what Codex will do, what the owner must do, and blockers.
- At each stage end report what is complete, unfinished, real, mocked or disconnected; run appropriate checks and report actual results. Give the exact browser address, startup steps and a practical click/test checklist with expected outcomes. Wait for review and incorporate requested revisions before advancing.
- Keep the plan, decision log and readiness register current. Clearly distinguish untested, blocked and verified work; do not claim a feature works without evidence.
- Explain technical terms and service setup for a beginner. Set up services only when needed; explain purpose, choices, likely cost, non-secret values, secure local or hosting secret placement, and success/failure testing. Never ask for secrets, passwords or OTPs in chat.
- Use test/sandbox integrations. No live customer messages or charges, deployment, publishing or live-service changes without a specific instruction. No stack change without explanation and discussion.
- Resolve only decisions needed for the current stage. Latest explicit instructions supersede older conflicts. Record uncertainty instead of inventing decisions.
- Customer frontend direction from the user: modern, easy to use, tells a story through pictures and background images, with floating icons where useful. Treat this as direction, not approval of specific artwork, colors or layout.
- Admin dashboard is a later stage. Before building or revising it, read the admin design reference and inspect both original videos if available, as required by the root AGENTS.md.
- Stage 0 is documentation and review only. Do not begin coding or the next stage until the owner reviews this plan and asks to proceed.
